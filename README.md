# bangumi-oped 接入文档

`bangumi-oped` 用于收录动漫番剧片头(OP)、片尾(ED)的时间戳数据,供第三方工具(播放器、插件、脚本等)接入使用,实现自动跳过片头片尾的功能。

## 1. 文件组织方式

- **每部番剧对应一个独立文件夹**,文件夹名为该番剧在 [Bangumi 番组计划](https://bgm.tv)(bgm.tv)上对应的**条目 ID(Subject ID)**。
- 文件夹内包含两类文件:
  1. **数据文件**:文件名与文件夹同名,格式为 `ID.txt`,存放实际的 OP/ED 时间戳数据(详见第 2 节)。
  2. **番剧名标记文件**:一个**空文件**,文件名为该番剧的名称(建议使用 bgm.tv 页面上显示的中文名,没有中文名则使用原名),**不包含任何内容**,仅用于人工浏览时快速识别该文件夹对应哪一部作品。

例如,番剧在 bgm.tv 上的条目地址为:

```
https://bgm.tv/subject/12345
```

对应的目录结构为:

```
12345/
├── 12345.txt        # 实际数据文件
└── 葬送的芙莉莲   # 番剧名标记文件(空文件,仅作人工识别用)
```

> 获取番剧的 Subject ID:打开该番剧在 bgm.tv 上的页面,URL 中 `/subject/` 后面的数字即为 ID。

> **番剧名标记文件说明**:
> - 该文件**内容永远为空**,仅文件名有意义,解析程序应完全忽略此文件,不参与任何数据解析逻辑。
> - 文件名中若包含文件系统不允许的字符(如 `:`、`/`、`\`、`?`、`*`、`"`、`<`、`>`、`|`,常见于 Windows 系统限制),需要替换或省略,推荐将这些字符统一替换为全角字符(如 `:` → `:`)或直接删除。
> - 命名建议以 bgm.tv 页面上的**中文名**为准,没有中文名时使用**原名**,保证名称权威、可追溯、不产生歧义。

## 2. 文件内容格式

文件内部**按行存储**,每一行对应**一集**,行内字段使用英文分号 `;` 分隔,固定 **5 个字段**:

```
集数;OP开始;OP结束;ED开始;ED结束
```

### 字段说明

| 字段 | 含义 | 单位 |
|---|---|---|
| 集数 | 第几集(从 1 开始) | 整数 |
| OP开始 | 片头起始时间 | 秒 |
| OP结束 | 片头结束时间 | 秒 |
| ED开始 | 片尾起始时间 | 秒 |
| ED结束 | 片尾结束时间 | 秒 |

### 示例

```
1;100;2300;2400;2500
2;110;2310;2410;2510
3;100;2300;2400;2500
```

表示:
- 第 1 集,OP 为 100~2300 秒,ED 为 2400~2500 秒。
- 第 2 集,OP 为 110~2310 秒,ED 为 2410~2510 秒。
- 第 3 集,OP 为 100~2300 秒,ED 为 2400~2500 秒。

## 3. 缺失 OP 或 ED 的情况

字段数量始终保持 **5 个不变**,**不允许留空**,不存在的字段必须使用 `-1` 作为占位值(哨兵值)填充,不能省略字段、不能删减字段数量,也不能改变字段顺序。

### 没有 OP(例如该集是特别篇、无片头)

```
2;-1;-1;2400;2500
```

### 没有 ED(例如该集是最终话,片尾被正片替代)

```
3;100;2300;-1;-1
```

### 既无 OP 也无 ED

```
4;-1;-1;-1;-1
```

> 使用 `-1` 而非留空或 `0`,是因为:
> - `0` 是合法的时间戳(片头可能从第 0 秒开始),不能用来表示"不存在"。
> - 留空(如 `2;;;2400;2500`)会破坏固定字段数的一致性,增加解析复杂度,**因此一律禁止留空**,缺失的每一个字段都必须显式写成 `-1`。

## 4. 跳集 / 非正片内容的处理

如果某一集是总集篇、OVA、特别篇等不计入正式集数,或者该集数据尚未收录,直接**跳过对应的集数行**即可,不需要用空行占位。集数字段本身就是显式的,不依赖行号顺序,因此跳过某几集不会影响其他行的解析。

例如,若第 2 集是总集篇不收录,文件可以是:

```
1;100;2300;2400;2500
3;100;2300;2400;2500
```

## 4.1 行的书写顺序

由于集数是**显式字段**,文件内各行的先后顺序**不影响解析结果**,以下两种写法在语义上完全等价:

```
2;110;2310;2410;2510
3;100;2300;2400;2500
```

```
3;100;2300;2400;2500
2;110;2310;2410;2510
```

- 解析方**不能假设文件是按集数升序排列**,必须以每行显式的集数字段为准,不能依赖行号或书写顺序。
- 为了便于人工阅读、Diff 审查和维护,**建议**贡献者按集数升序书写,但这**不是强制要求**,乱序提交同样会被接受。

## 4.2 集数重复时的处理

正常情况下,同一文件内不应该出现同一集数重复的行,但由于集数是显式字段、行的顺序也不做强制校验,实际使用中仍可能出现手滑、合并冲突等原因导致同一集数被重复写入的情况。

对于这种情况:

- **不强制要求文件内绝对不能出现重复集数**,但贡献者应尽量避免。
- 解析方**不应假设文件内集数一定唯一或严格递增**,应按正常顺序遍历整个文件。
- 若遍历过程中遇到重复的集数,**以第一次出现的一行为准,忽略之后出现的同集数行**,不需要报错或做特殊处理。

也就是说,贡献者不应依赖"后写的行会覆盖前面的行"这种写法来做修正,如果发现某一集数据有误,应该直接修改或删除原来的那一行,而不是在文件末尾追加一行新的同集数数据。

## 5. 第二季及以后作品的集数记录方式

部分作品在 bgm.tv 上,第二季(或后续季度)会被拆分为**独立的条目(独立的 Subject ID)**,但集数编号却延续第一季末尾继续计数,例如第二季在 bgm.tv 页面上显示的第 1 集实际编号为"第 13 集"。

对于这种情况,**本项目统一按该条目自身的集数从 1 开始记录**,不使用 bgm.tv 页面上显示的连续集数。

例如某作品第二季在 bgm.tv 上对应 Subject ID 为 `54321`,页面显示的集数为 13~24 集,则 `54321/54321.txt` 文件中应记录为:

```
1;100;2300;2400;2500
2;110;2310;2410;2510
...
12;100;2300;2400;2500
```

而**不是**:

```
13;100;2300;2400;2500
14;110;2310;2410;2510
...
24;100;2300;2400;2500
```

> 原则:**集数字段始终对应"该 Subject ID 文件内部的第几集",而不是 bgm.tv 页面上显示的全系列连续集数**。每个 Subject ID 对应一个独立文件,文件内部集数固定从 1 开始编号。

## 6. 接入 / 解析示例

以下是一个简单的解析逻辑示意(伪代码):

```python
import os

def parse_bangumi(subject_id, base_dir="."):
    folder = os.path.join(base_dir, str(subject_id))
    filepath = os.path.join(folder, f"{subject_id}.txt")  # 只读取 ID.txt,忽略番剧名标记文件

    episodes = {}
    with open(filepath, encoding="utf-8") as f:
        for line in f:
            line = line.strip()
            if not line:
                continue
            ep, op_start, op_end, ed_start, ed_end = line.split(";")
            episodes[int(ep)] = {
                "op": None if op_start == "-1" else (int(op_start), int(op_end)),
                "ed": None if ed_start == "-1" else (int(ed_start), int(ed_end)),
            }
    return episodes
```

调用方只需要:

1. 根据番剧的 bgm.tv Subject ID 定位到对应文件夹,读取其中的 `ID.txt`(**忽略同目录下的番剧名标记空文件**)。
2. 按行解析,取出当前集数对应的 OP/ED 区间。
3. 若某一时间段为 `None`(即原始值为 `-1`),说明该集没有对应片段,播放器/插件应跳过"跳过"按钮的展示或相关逻辑。

## 7. 贡献数据须知

- 提交新番剧数据时,请为该番剧创建以 **Subject ID** 命名的文件夹,内含 `ID.txt` 数据文件和番剧名标记空文件,确保与官方条目一一对应,避免命名冲突或指向错误的作品。
- 番剧名标记文件**内容必须为空**,仅文件名用于人工识别,提交前请核对文件夹名(ID)与番剧名标记文件是否匹配,防止张冠李戴。
- 每一行必须保持 5 个字段,**禁止留空**,缺失 OP/ED 时按第 3 节的方式使用 `-1` 占位(如 `-1;-1;2400;2500` 或 `2;-1;-1;-1;-1`)。
- **同一集数尽量避免重复出现**;若确实出现重复,解析时以第一次出现的一行为准,后面的重复行会被忽略,因此请勿依赖"后写覆盖前面"的方式修正数据,发现错误应直接修改原有行。
- 文件内各行顺序不影响解析,但建议按集数升序书写,便于审查和维护。
- 若该作品为第二季及以后的续作,且 bgm.tv 使用连续集数编号,请按第 5 节说明,**从 1 开始重新记录集数**,不要沿用 bgm.tv 页面上的连续集数。
- 欢迎通过 Pull Request 的方式提交或修正数据。
